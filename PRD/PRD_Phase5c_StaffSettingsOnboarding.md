# PRD — Phase 5c: Staff, Settings & Onboarding
### Trapezi · Version 1.1 · April 22, 2026

---

## 1. Goals

- Allow owners to create and manage staff accounts with roles, names, emails, auto-generated passwords and PINs
- Implement email + password login for full authentication; PIN-only for lock screen resume
- Implement a PIN lock screen that activates after configurable inactivity — cashier can never be auto-logged out
- Give owners full branding control (Basic: logo + accent color; Pro: everything)
- Allow owners to configure printer IPs from the dashboard
- Provide a visual iPad PWA onboarding guide inside Settings
- Allow owners to manage tables individually and group them into sections (Pro)

---

## 2. Non-Goals

- No customer-facing accounts or logins
- No biometric authentication
- No multi-iPad support per restaurant in this phase
- No kitchen or bar routes, accounts, or roles — ever
- No free-form font upload — curated list only
- No staff self-service credential management — all managed by owner

---

## 3. User Stories

**Staff Management:**
> As an owner, I want to create staff accounts with name, email, role, auto-generated password and PIN so I can hand credentials directly to my staff.

> As an owner, I want to reset a staff member's password or PIN with a newly generated value so I can help them if they forget.

> As an owner, I want to see a staff member's current PIN and password so I can share it with them.

> As an owner, I want to deactivate a staff member without deleting their account so order history is preserved.

**Authentication:**
> As any staff member, I want to log in with my email and password at the start of my shift.

> As a cashier, I want the screen to PIN-lock after inactivity but never fully log me out so I can resume instantly.

> As an owner or manager, I want the screen to PIN-lock after inactivity and fully log me out after too many failed PIN attempts.

**Branding:**
> As a Basic owner, I want to upload my logo and set an accent color so my menu feels on-brand.

> As a Pro owner, I want to fully customize the look of my customer menu including font, colors, confirmation message, and receipt text.

**Settings:**
> As an owner, I want to configure my printer IPs from the dashboard so I don't need developer access.

> As an owner, I want to set the inactivity timeout duration for PIN lock so I can decide how quickly the screen locks.

**Table Management:**
> As an owner, I want to add, edit, and remove tables with a number, name, and capacity.

> As a Pro owner, I want to group tables into sections so the cashier screen is easier to navigate.

**Onboarding:**
> As an owner or hardware friend, I want a step-by-step visual guide inside the dashboard to set up the iPad as a PWA.

## 4. Feature Breakdown

### 4.1 Staff Management (All paid plans)

Owner creates staff accounts with:
- Full name
- Email address
- Role: `cashier`, `manager`, or `owner`
- Password: auto-generated by system, shown to owner once, copyable
- 4-digit PIN: auto-generated by system, shown to owner, copyable

Owner can at any time:
- View current PIN and password for any staff member
- Regenerate password (new auto-generated value replaces old)
- Regenerate PIN (new auto-generated value replaces old)
- Toggle active/inactive status
- Delete staff (soft delete — sets `deleted_at`, preserves order history)

Constraints:
- Max 1 cashier account per restaurant
- Max 1 manager account per restaurant
- Unlimited owner accounts
- Add button disabled with tooltip when cashier/manager limit reached

Deactivated staff: cannot log in. Session invalidated immediately.

### 4.2 Authentication Model

**Full login (session creation):**
- Staff navigates to `/[slug]/login`
- Enters email + password
- On success: Supabase session created, redirect based on role
  - cashier → `/[slug]/cashier`
  - manager/owner → `/[slug]/owner`
- On failure: "Incorrect email or password"
- Passwords managed via Supabase Auth — auto-generated by owner dashboard, never set by staff

**PIN lock screen (session resume):**
- Activates after configurable inactivity timeout (all roles)
- Full-screen overlay — does not destroy session, does not navigate away
- Shows restaurant logo (if set), staff first name, 4-digit PIN pad
- On correct PIN: overlay dismissed, session resumes instantly
- On incorrect PIN: shake animation, increment failure counter
- After 5 failed attempts:
  - Cashier: stays on PIN lock screen, cannot be fully logged out
  - Owner/Manager: full logout, redirect to `/[slug]/login`

**Cashier-specific rules:**
- PIN lock is the maximum escalation — never auto-logged out
- Full logout ONLY via explicit "End Service" button
- "End Service" requires PIN confirmation before logging out

**Inactivity detection:**
- Track `mousemove`, `keydown`, `touchstart`, `click` on `window`
- Reset timer on any event
- On expiry: show PIN lock overlay
- Implemented as `InactivityProvider` React context wrapping cashier and owner layouts

### 4.3 Branding Settings

**Basic plan:**
- Logo upload → Supabase Storage bucket: `restaurant-assets`
- Primary accent color: color picker

**Pro plan (all of the above plus):**
- Font: dropdown — Inter, Playfair Display, Lora, Montserrat, Raleway
- Secondary color: color picker
- Custom confirmation message (bilingual — DeepL auto-translates)
- Custom receipt header text
- Custom receipt footer text

All stored in `restaurants.metadata.branding`:
```json
{
  "logo_url": "string",
  "accent_color": "#hex",
  "secondary_color": "#hex",
  "font": "string",
  "confirmation_message_el": "string",
  "confirmation_message_en": "string",
  "receipt_header": "string",
  "receipt_footer": "string"
}
```

Live preview panel on the right side of branding settings:
- Mock customer menu card showing logo, colors, font, sample item
- Updates in real time as owner changes settings
- Not a full page preview — representative card only

Branding applied to customer menu at `/[slug]`:
- Accent color as CSS custom property `--color-accent`
- Font loaded via Google Fonts link tag (Pro only)
- Logo in menu header
- Confirmation message shown post-order (Pro only)

Receipt slips (thermal printer):
- Prepend `receipt_header` if set (Pro only)
- Append `receipt_footer` if set (Pro only)

### 4.4 Printer Configuration (Basic + Pro)

Three printer slots:
- Kitchen printer — IP address input
- Bar printer — IP address input
- Cashier printer — IP address input

Each slot:
- IPv4 validation on input
- "Test connection" button — pings via QZ Tray, shows ✅ or ❌
- Clear button

Saved to `restaurants.metadata.printers` (existing structure).

### 4.5 Inactivity Timeout Setting (Basic + Pro)

Settings → Security:
- Label: "Lock screen after inactivity"
- Dropdown: 5 / 10 / 15 / 20 / 30 minutes
- Default: 15 minutes
- Applies to all roles including cashier
- Stored in `restaurants.metadata.inactivity_timeout_minutes`

### 4.6 Table Management (Basic + Pro)

Each table has:
- Number (required, integer, unique per restaurant)
- Name (optional, e.g. "Window Seat", "Bar Stool 1")
- Capacity (optional, integer)
- Section assignment (Pro only — dropdown of sections)

Actions:
- Add table
- Edit table (all fields)
- Delete table — soft delete (`deleted_at`). If table has open orders: "This table has an open tab. Close the tab before deleting."

**Sections (Pro only):**
- Owner creates named sections: "Terrace", "Indoor", "Bar" etc.
- Tables assigned to sections via dropdown on table edit form
- Deleting a section: tables become unassigned, not deleted
- Sections shown as collapsible groupings on cashier screen left panel

### 4.7 iPad PWA Onboarding Guide (Basic + Pro)

Settings → Onboarding. Five steps:

1. **Open Safari** — "Make sure you are using Safari. PWA installation is not supported in Chrome or Firefox on iOS."
2. **Navigate to cashier URL** — restaurant's cashier URL shown as copyable link
3. **Add to Home Screen** — tap Share (📤), scroll down, tap "Add to Home Screen", confirm
4. **Open from Home Screen** — "Always open from the Home Screen icon, never from Safari directly."
5. **Enable notifications** — "When prompted, tap Allow to enable push notifications."

Each step has a manual ✅ checkbox. State stored in `localStorage` on the device — not in DB.

## 5. Technical Specification

### 5.1 New Migration: `009_phase5c_staff_settings.sql`

```sql
-- Add columns to staff
ALTER TABLE staff
  ADD COLUMN IF NOT EXISTS pin_hash text,
  ADD COLUMN IF NOT EXISTS failed_pin_attempts int NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS locked_until timestamptz,
  ADD COLUMN IF NOT EXISTS deleted_at timestamptz;

-- Create sections table
CREATE TABLE sections (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  restaurant_id uuid NOT NULL REFERENCES restaurants(id) ON DELETE CASCADE,
  name text NOT NULL,
  display_order int NOT NULL DEFAULT 0,
  created_at timestamptz NOT NULL DEFAULT now()
);
ALTER TABLE sections ENABLE ROW LEVEL SECURITY;

-- Add columns to tables
ALTER TABLE tables
  ADD COLUMN IF NOT EXISTS name text,
  ADD COLUMN IF NOT EXISTS capacity int,
  ADD COLUMN IF NOT EXISTS section_id uuid REFERENCES sections(id) ON DELETE SET NULL,
  ADD COLUMN IF NOT EXISTS deleted_at timestamptz;

-- RLS: sections
CREATE POLICY "staff can read sections" ON sections FOR SELECT USING (
  restaurant_id IN (
    SELECT restaurant_id FROM staff WHERE user_id = auth.uid()
  )
);
CREATE POLICY "owner or manager can manage sections" ON sections FOR ALL USING (
  restaurant_id IN (
    SELECT restaurant_id FROM staff
    WHERE user_id = auth.uid() AND role IN ('owner', 'manager')
  )
);

-- Indexes
CREATE INDEX IF NOT EXISTS idx_sections_restaurant ON sections(restaurant_id);
CREATE INDEX IF NOT EXISTS idx_tables_section ON tables(section_id);
CREATE INDEX IF NOT EXISTS idx_staff_deleted ON staff(deleted_at);
```

### 5.2 Password Management

- Supabase Auth used for session management (required for RLS)
- Passwords are auto-generated by the owner dashboard using `crypto.randomBytes` or similar — 12 character alphanumeric string
- Owner creates staff via Supabase Admin API (`supabase.auth.admin.createUser`) with the generated password
- Password is shown to owner once in the dashboard — owner copies and hands to staff
- Staff never set or change their own password
- Password reset: owner generates new password via `supabase.auth.admin.updateUserById`, shown in dashboard

### 5.3 PIN Management

- 4-digit numeric PIN auto-generated by owner dashboard
- Stored as bcrypt hash in `staff.pin_hash`
- Never stored or returned in plain text after creation — shown once at creation/reset
- PIN verify: hash incoming PIN, compare to `pin_hash`
- Failed attempts tracked in `staff.failed_pin_attempts`
- Lock: `locked_until = now() + 10 minutes` after 5 failures

### 5.4 New API Routes

| Route | Method | Purpose |
|---|---|---|
| `/api/staff` | GET, POST | List or create staff |
| `/api/staff/[id]` | PATCH, DELETE | Edit or deactivate staff |

| `/api/staff/[id]/reset-pin` | POST | Owner generates new PIN |

| `/api/settings/branding` | GET, PATCH | Read/update branding |
| `/api/settings/printers` | GET, PATCH | Read/update printer IPs |
| `/api/settings/security` | GET, PATCH | Read/update inactivity timeout |
| `/api/tables` | GET, POST | List or create tables |
| `/api/tables/[id]` | PATCH, DELETE | Edit or soft-delete table |
| `/api/sections` | GET, POST | List or create sections |
| `/api/sections/[id]` | PATCH, DELETE | Edit or delete section |

### 5.5 InactivityProvider

Create `components/providers/InactivityProvider.tsx`:
- Reads `inactivity_timeout_minutes` from restaurant settings on mount
- Listens to `mousemove`, `keydown`, `touchstart`, `click` on `window`
- Resets timer on any event
- On expiry: sets `isLocked = true`
- Renders `<PinLockScreen />` as full-screen overlay when locked
- `PinLockScreen` calls `/api/auth/pin-verify`
- On success: `isLocked = false`
- Cashier: on 5 failed PIN attempts → stays locked, no logout
- Owner/Manager: on 5 failed PIN attempts → `supabase.auth.signOut()`, redirect to login

Wrap `app/[slug]/cashier/layout.tsx` and `app/[slug]/owner/layout.tsx` with this provider.
